- Production-contract role/tier normalization and the catalogue audit live only in `supabase/functions/_shared/productionContract.ts` (adapter re-exports it) — one deterministic legacy repair, so no path can grant a `source` role to an input-consuming recipe.
- The labour market is one two-pass allocation in `goodsEconomy.ts`: sector-native fill, then retraining limited by `ECONOMY.laborMobility` (guild, admin, market, stability); leftover idle labour next to vacancies is reported as `structural_unemployed` — one place decides staffing, so UI never re-derives employment.
- Trade-service GDP uses `productMarket.tradeServiceVolumes` at catalogue prices; never feed nominal flow.gross_value into constant-price service GDP.
- Route pricing for both actual sourcing (goodsEconomy) and AUTO planning (economyAdapter) lives only in `_shared/landedRoute.ts`; a missing/unreachable/war-blocked input is `available:false`, never zero-cost — so planning can never rank suppliers differently from the physical solver.
- Recipe input classes A material / B factor / C operating live only in `supabase/functions/_shared/inputKinds.ts` (carried in `production_recipes.input_items[].kind`); solver, AUTO planning, catalogue audit and Dev Mode cost all read it, and a producer with an explicit B tools factor is excluded from city-level tool wear — one classification, no double wear charge.
- Wage settlement (producer→household, treasury effect 0) lives only in `supabase/functions/_shared/wageSettlement.ts`, called only by process-turn and persisted via the fiscal plan — one settlement, retries never pay twice.
- Army micro-square movement rules (costs, budget, 200 men per sub-square, path validation, default camp square) live only in `_shared/microMovement.ts`; the map preview imports it and command-dispatch re-validates via `applyStackMicroMove` — preview and server can never disagree on reach.
- Micro-square resources (certain by sub-biome, hidden chances gated by macro deposits, survey cost) live only in `_shared/microResources.ts`; surveys are written only by `record_micro_survey` via command-dispatch SURVEY_MICRO and read owner-only from `micro_surveys`; rural sites build only where `microSiteReason` confirms a recipe resource (certain or own survey) — one gate for UI hint and server.
- Farm fields (max 8, adjacent chain, arable, same city) live only in `_shared/farmFields.ts`; written only by `add_farm_field` via command-dispatch ADD_FARM_FIELD; economyAdapter folds live fields into the farm site capacity/jobs and skips field parcels as own producers — one physical source per field.
- Crop spreading (plantable kinds, suitability, 3-turn maturity, cost) lives only in `_shared/cropSpread.ts`; plantings are written only by `plant_crop` via command-dispatch PLANT_CROP, count as a confirmed micro resource for site gating, and economyAdapter zeroes the crop recipe on that parcel until mature — no early harvest.
- Micro sieges: rules (walls, breach chance, attacker-first then issue order, one action per 200-men unit) live only in `_shared/siege.ts`, live units in `_shared/siegeState.ts`; orders only via command-dispatch START_SIEGE/SIEGE_ORDER, settled only in commit-turn via `apply_siege_turn` (idempotent by last_resolved_turn) — one resolver, no double losses.
