- Trade-service value added (`productMarket.tradeServiceValue`) is part of city_gdp and realm value_added_gdp; gross trade never is.
- Household income uses one global PRODUCT_MARKET.incomeUnitFactor, never the city CPI; product choice/budget cap read previous COMMITTED prices (snapshot.priorPrices) — so local inflation is visible and there is no same-pass price loop.
- Population never yields wealth: `computeCityLayerEconomy` has no wealth layer; fiscal revenue comes solely from the canonical tax pillars and goods ledger.
- Treasury reconciliation lives in `_shared/treasury.ts`; UI reads the persisted complete breakdown. Legacy trade net already includes tolls.
- `finish_turn_resolution` alone publishes the calendar after mandatory phases. `resolving_turn` is the internal economy target; refresh/player commands must not overlap it.
- Turn-phase/fiscal planners buffer writes; SQL applies effects and completion guards atomically. Do not add direct fiscal writes outside the plan. External combat/AI interrupted before the physical checkpoint remain fail-closed; never mark partial ticks completed just to unblock the game.
- City accounts/product choice reach the UI only inside the owner-scoped management report (`read_economy_management`); authenticated users never read `economy_turn_ledgers` directly.
- Access boundary: anon has no table access (no public route); session data is readable only by session members via `app_private.is_session_member`; server-written tables are SELECT-only for clients, internal projections/journals/locks/AI state are service_role-only, and fiscal/turn columns (realm_resources treasury, game_sessions turn fields, game_players.player_name) are never client-writable — so canonical state can only change through edge functions/RPCs.

- Admin/dev panel writes go only through the `admin-dev-write` function (`src/lib/devAdminDb.ts`; policy in `admin-dev-write/policy.ts`): admin role, session scope, table allowlist, forbidden turn/victory columns, audit row — so dev tooling never reopens direct table writes.

- World-creation player settings are normalized and mapped to concrete numbers only in `supabase/functions/_shared/worldGameSettings.ts`; every creation step (map, preview, neutral towns, init) reads it — one source for what each choice means.

- Per-city subsistence readout (food status, labour headcount) lives only in `supabase/functions/_shared/subsistence.ts`, reusing `foodShortageImpact`; both secure reports embed it and UI renders it via `SubsistencePanel` — rationing vs famine can never disagree with process-turn.
- Session-member RLS on owned entities is SELECT for members and INSERT/UPDATE/DELETE only via `app_private.is_realm_owner` on the row's owner column (or admin); config tables (server_config, economy_overrides) are admin-write — so a member can never mutate another realm's rows from the client; edge functions use service_role.
- game_events: members read; clients insert/update only their own narrative events (guard trigger `guard_client_game_event` blocks server-resolved types, command/processed rows and identity edits); delete is admin-only — so canonical mechanics events come only from edge functions.
- Starter water/food sources come only from `starterGeography` in `supabase/functions/_shared/starterEconomy.ts` (river = fresh water, sea never; wild biomes = small fixed hunting) — one place decides what a seat's geography allows.
- Versioned parcel extraction is defined only in `_shared/parcelEconomy.ts` and staffed by goodsEconomy; ecological closing state lives in committed ledgers, and `_shared/parcelRollout.ts` applies snapshot-backed atomic claims — refresh cannot harvest twice or mutate saves.

- Parcel rollout dry-runs validate both unapplied and already-applied saves through `_shared/parcelPreflight.ts`, preserving first-step adapter sources and rolling physical stores/ecology forward — an idempotent rollout must not hide subsistence failures or mint replenished opening stocks.

- Mechanics audit code-review evidence lives in `src/lib/hexNodeAudit.ts`; session LIVE counts are separate read-only queries with errors shown as unavailable — catalogue presence never establishes runtime correctness.

- Strategic resource tier effects live only in `supabase/functions/_shared/strategicEffects.ts` (process-turn, resolve-battle, command-dispatch import it) — no config drift between turn report, battles and build costs.
- Macro geology lives only in `supabase/functions/_shared/geology.ts` (private salt in service-only `geology_seeds`, ground truth in service-only `macro_deposits`); players read only their own `macro_surveys`; macro claim/province changes go only through `claim_macro_tile`/`assign_macro_province` RPCs via command-dispatch — no survey spoilers, no disconnected or foreign claims.
