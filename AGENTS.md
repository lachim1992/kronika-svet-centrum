- Product choice, diversity, city accounts and recipe margins live only in `supabase/functions/_shared/productMarket.ts`; the UI reads `economy_turn_ledgers.result.cityAccounts/productChoice` and never recomputes them — single source of truth for new economy formulas.
- Player builds resolve from `building_templates` server-side (`_shared/buildValidation.ts`); client cost/effects are ignored — one authority for prerequisites.
- `city_capital_stock` is written only by process-turn (formula `productMarket.capitalStockDelta`); refresh shows the candidate only — no second accumulator.
- Trade-service value added (`productMarket.tradeServiceValue`) is part of city_gdp and realm value_added_gdp; gross trade never is.
- Household income uses one global PRODUCT_MARKET.incomeUnitFactor, never the city CPI; product choice/budget cap read previous COMMITTED prices (snapshot.priorPrices) — so local inflation is visible and there is no same-pass price loop.
- Production-contract role/tier normalization and the catalogue audit live only in `supabase/functions/_shared/productionContract.ts` (adapter re-exports it) — one deterministic legacy repair, so no path can grant a `source` role to an input-consuming recipe.
- Population never yields wealth: `computeCityLayerEconomy` has no wealth layer; fiscal revenue comes solely from the canonical tax pillars and goods ledger.
- The labour market is one two-pass allocation in `goodsEconomy.ts`: sector-native fill, then retraining limited by `ECONOMY.laborMobility` (guild, admin, market, stability); leftover idle labour next to vacancies is reported as `structural_unemployed` — one place decides staffing, so UI never re-derives employment.
- Treasury reconciliation lives in `_shared/treasury.ts`; UI reads the persisted complete breakdown. Legacy trade net already includes tolls.
- Trade-service GDP uses `productMarket.tradeServiceVolumes` at catalogue prices; never feed nominal flow.gross_value into constant-price service GDP.
- `finish_turn_resolution` alone publishes the calendar after mandatory phases. `resolving_turn` is the internal economy target; refresh/player commands must not overlap it.
- Turn-phase/fiscal planners buffer writes; SQL applies effects and completion guards atomically. Do not add direct fiscal writes outside the plan. External combat/AI interrupted before the physical checkpoint remain fail-closed; never mark partial ticks completed just to unblock the game.
- Route pricing for both actual sourcing (goodsEconomy) and AUTO planning (economyAdapter) lives only in `_shared/landedRoute.ts`; a missing/unreachable/war-blocked input is `available:false`, never zero-cost — so planning can never rank suppliers differently from the physical solver.
- City accounts/product choice reach the UI only inside the owner-scoped management report (`read_economy_management`); authenticated users never read `economy_turn_ledgers` directly.
- Access boundary: anon has no table access (no public route); session data is readable only by session members via `app_private.is_session_member`; server-written tables are SELECT-only for clients, internal projections/journals/locks/AI state are service_role-only, and fiscal/turn columns (realm_resources treasury, game_sessions turn fields, game_players.player_name) are never client-writable — so canonical state can only change through edge functions/RPCs.
- game_sessions has no client UPDATE grant: lobby settings, seat names, generation status and story ending go through creator/admin-checked RPCs (`update_session_lobby`, `sync_session_player_names`, `set_session_generation_status`, `end_story_session`) — turn/victory/era/tier/init state stays server-authoritative.
- Admin/dev panel writes go only through the `admin-dev-write` function (`src/lib/devAdminDb.ts`; policy in `admin-dev-write/policy.ts`): admin role, session scope, table allowlist, forbidden turn/victory columns, audit row — so dev tooling never reopens direct table writes.
- Session-scoped edge functions authorize callers with `_shared/sessionAuth.ts` (JWT → member/creator/admin, or internal service key); body-supplied player names are never identity.
